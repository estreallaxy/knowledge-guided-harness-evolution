# Evaluation Archive Guided Search

## 什么时候使用

| 判断 | 内容 |
| --- | --- |
| 要解决的问题 | 优化 agent 提出的候选修改缺乏结构化验证记录，反馈不能有效指导下一轮搜索；失败尝试被丢弃而非复用。 |
| 使用前提 | 每次迭代有可运行的任务评估；评分信号可靠；存档可随迭代增长；允许把存档内容注入下一轮生成提示。 |
| 输入 | 任务描述、候选修改（代码/设计）、任务评估函数、存档（历史候选 + 分数 + 错误日志 + 反思）。 |
| 输出 | 带评分的候选存档，以及注入成功/失败样例后的下一轮生成提示。 |
| 不使用 | 没有可重复执行的任务评估（无法产生可信分数）；评分噪声大于候选间差异；或存档会泄露封存测试集信息时（必须先做信息隔离）。 |
| 主要风险 | 每次迭代都要完整任务评估，成本高；存档质量依赖评分可靠；失败样例可能把优化引向局部修补；存档只作启发，不保证收敛。 |

## 怎么工作

1. 每个候选修改在任务上评估，得到 (设计, 分数, 错误日志, 反思) 四元组。
2. 四元组存入不断增长的存档；候选无论成败都保留（失败候选附 error-repair 步骤）。
3. 生成下一轮候选前，从存档检索 top-k 成功样例与最近失败样例，注入生成提示作为启发素材。
4. 新候选经评估后回写存档；存档随迭代滚动更新，记录保留来源与时间。

本方法改造的是 harness 优化闭环中的验证与反馈模块，不改变执行任务本身。论文（ADAS）的 archive 不区分成功/失败注入比例，本实现显式分开检索，便于消融「成功样例启发」与「失败修复引导」各自的贡献。

方法关系：依赖可重复执行的任务评估器。可与 [Action-Observation Event Stream](../action-observation-event-stream/README.md) 组合（从事件流提取评估与失败信号）；可与 [Nested Subagent Delegation](../nested-subagent-delegation/README.md) 组合（用评分存档挑选委派方案）。与人工检视轨迹的验证方式是替代关系。以上组合均为待实验验证的假设，尚无本地证据。

## 直接运行

```bash
python code/score_archive.py demo
```

| 文件 | 用途 |
| --- | --- |
| [`code/score_archive.py`](code/score_archive.py) | 候选记录、评分存档、top-k 检索与引导提示生成的机制骨架。 |
| [`code/archive_prompt.md`](code/archive_prompt.md) | 把存档样例注入下一轮候选生成提示的模板。 |
