# Agent-Computer Interface

## 什么时候使用

| 判断 | 内容 |
| --- | --- |
| 要解决的问题 | 工具接口与观测反馈没有针对模型设计：动作粒度不当、编辑无语法保护、反馈信息量失衡，模型把预算浪费在无效动作与格式纠错上。 |
| 使用前提 | 工具层可作为固定命令集统一包装（查看 / 编辑 / 搜索等）；动作可做写后预检（至少编辑可做语法检查）；观测反馈格式可自定义。 |
| 输入 | 命令（窗口化查看、范围编辑、目录搜索等）、参数、文件系统状态、可注入的语法检查器。 |
| 输出 | 面向模型的观测反馈：带行号与窗口位置的文件片段、编辑确认或语法错误自动回退、无输出时的明确状态说明。 |
| 不使用 | 工具层只能原样暴露（无法包装命令）；或任务不涉及文件查看与编辑时收益有限。 |
| 主要风险 | 语法 guardrail 误报导致合法编辑被回退；窗口过小切断上下文、过大淹没关键信息；反馈格式被下游依赖后修改会波及既有轨迹与诊断工具。 |

## 怎么工作

1. 工具层统一为少量固定命令（查看、编辑、搜索等）；命令集本身就是可插拔的扩展点。
2. 查看命令窗口化：每次显示固定行数（论文默认 100 行）并带行号，支持滚动与内容检索定位。
3. 编辑命令带语法 guardrail：写回后立即做语法检查，失败则自动回退原文件并把错误反馈给执行方。
4. 反馈信息量设计：命令成功但无输出时明确告知（如「命令成功运行且没有产生输出」），避免把「无反馈」误判为失败而重试。

本方法改造的是 harness 的工具层与观测层，不改变执行模型与任务逻辑。guardrail 的检查器可注入（本实现默认对 Python 文件用 `ast.parse`），反馈格式化集中在单一入口，便于下游解析。

方法关系：可作为 [Action-Observation Event Stream](../action-observation-event-stream/README.md) 的动作类型与反馈契约来源（组合关系）；窗口化查看与编辑 guardrail 可作为 Lifecycle Kernel Services（其他方向，未在本分支登记）中工具服务的具体实现候选。与直接暴露原始 shell 是替代关系。以上组合均为待实验验证的假设，尚无本地证据。

## 直接运行

```bash
python code/aci_toolkit.py demo
```

| 文件 | 用途 |
| --- | --- |
| [`code/aci_toolkit.py`](code/aci_toolkit.py) | 窗口化查看器、带语法 guardrail 的编辑器与反馈格式化的机制骨架；语法检查器可注入。 |
代码仅依赖 Python 标准库，无需安装依赖。

论文结果、固定版本映射和核验状态保存在 [`evidence/`](evidence/)，仅在审计方法来源或研究结论时读取。
