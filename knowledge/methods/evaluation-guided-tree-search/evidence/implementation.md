# 实现依据

核对代码来源：`FoundationAgents/AFlow`（论文对应 ICLR 2025 Oral 版实现）。关键位置按上游模块粒度标注，精确文件路径待对照固定版本复核。

| 环节 | 论文/上游行为 | 关键位置 |
| --- | --- | --- |
| 工作流即代码 | 候选工作流用节点 + 边的代码表示，可执行、可修改 | 工作流模板与算子定义 |
| MCTS 搜索 | 以评估分数为回报，在代码表示的工作流空间上做蒙特卡洛树搜索（选择为 soft mixed-probability selection，原文无 UCB 表述） | 搜索脚本 |
| 变异算子 | 用 LLM 对工作流代码做结构 / 提示级别的修改（增删节点、改提示等） | 提示模板集合 |
| 执行反馈 | 节点执行结果（含失败）回流为评估信号 | 执行与评估模块 |

## 输入输出约定

```text
种子候选 + 评估器（候选 → 分数）+ 变异算子集合 + 搜索预算
                    ↓
   选择：soft mixed-probability（本骨架以 UCB1 近似利用/探索权衡）→ 选中节点轮转扩展一个算子 → 评估分数
                    ↓
   访问次数与总分沿路径回传；重复直至预算用尽
                    ↓
   全树最优候选 + 搜索历史（每次扩展的算子与分数）
```

## 本仓库代码

[`../code/tree_search.py`](../code/tree_search.py) 按上述机制重新实现为与 harness 无关的骨架，而非复制上游代码。差异：候选为纯文本，不包含上游的工作流代码解析与执行组件；变异算子与评估器均以回调注入，demo 用数值算子离线演示搜索动态，不调用模型；提示模板另见 [`../code/search_prompt.md`](../code/search_prompt.md)。迁移到 Terminus-KIRA 时，以「候选 harness 补丁 → 评估分数」接入评估器，先验证固定预算下的评估吞吐，再考虑多算子组合。

上游仓库当前未复制进仓库；其运行依赖和可复现性仍需通过实际复现确认。
