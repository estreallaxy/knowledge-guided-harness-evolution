A. Details of PSBench
A.1. Evaluation Functions
This section details the implementation and mechanism of our evaluation functions. According to the complexity of the
tasks, we adopt a hierarchical evaluation strategy:

 • Pixel-level / mathematically defined tasks (e.g., flip, rotation, scaling): evaluated directly using traditional computer
   vision algorithms (see A.1.1);
 • Semantic understanding and perceptual quality tasks (e.g., color adjustment, style transfer, artistic effects): because
   pixel-level metrics cannot accurately judge completion, we introduce a large vision-language model (GPT-4o) as an
   intelligent evaluator to semantically understand and judge the edited image (see A.1.2).

A.1.1. T RADITIONAL A LGORITHM -BASED E VALUATION
For image transformation tasks with clear mathematical definitions, we compute the similarity between the expected result
and the actual result to measure task completion quality. For example, in the image flip task, we implemented a flip accuracy
check function that quantifies the correctness of the flip operation using the Structural Similarity Index (SSIM).
Instruction: Flip the image vertically.
Evaluation Function:

    Flip Accuracy Check Function

    def check_flip_accuracy(self, parameters):
        """Check flip accuracy (specifically for flip tasks)"""
        direction = parameters.get('direction', 'vertical')
        tolerance = parameters.get('tolerance', 0.2)
        try:
            # Load original and result images
            start_img, result_img = self.load_task_images(comparison_type="start")
            # Perform expected flip
            if direction == 'vertical':
                expected_flip = np.flipud(start_img)
            elif direction == 'horizontal':
                expected_flip = np.fliplr(start_img)
            else:
                return {"passed": False,
                         "message": f"Unsupported flip direction: {direction}"}
            # Compute similarity
            similarity = ssim(expected_flip, result_img,
                               multichannel=True, channel_axis=2)
            passed = similarity >= (1.0 - tolerance)
            return {
                "passed": passed,
                "message": f"Flip accuracy: {similarity:.3f}, "
                            f"threshold: {1.0 - tolerance}",
                "similarity": similarity
            }
        except Exception as e:
            return {"passed": False,
                     "message": f"Flip accuracy detection failed: {str(e)}"}

tasks, focusing on the naturalness, aesthetic quality, and semantic consistency of the expected effects. To verify the reliability
of this automated framework, we conducted a rigorous consistency analysis on a subset of PSBench. By randomly sampling

A.5. Visualization of the Agent Execution Pipeline
In this subsection, we provide a concrete example of the GUI Agent workflow using the task “Add lighting effect to the
oil lamp in the image.” as an illustrative case. The initial input to the GUI Agent consists of two components: (1) the task
instruction, and (2) the initial screenshot, which includes both the unedited source image and the full Photoshop interface.
Starting from Step 2 (i.e., for all n ≥ 2), each step receives two inputs:

   • the updated screenshot obtained after executing the action from Step (n − 1), and

   • the accumulated memory from the previous (n − 1) steps, which stores the agent’s intermediate reasoning, state
     analysis, and action planning.

As shown in Table 7, the workflow is decomposed into four synchronized components: (1) Step n indicates the current
reasoning step; (2) Screenshot provides the interface state after executing Step (n − 1); (3) Agent Response contains the
model’s analysis of the current state and justification for the next action; (4) Action Code is the executable Python code
issued by the agent to interact with Photoshop.
Overall, the screenshot produced after each executed action becomes the visual input for the next reasoning step, forming a
closed-loop, step-by-step interaction cycle. This design ensures that the GUI Agent maintains coherent reasoning, stable
grounding, and controlled execution throughout multi-step editing tasks.
After the task is completed, the benchmark automatically saves the edited result and invokes the evaluation function to
assess its quality. At the same time, it extracts the agent’s internal action trajectory from the GUI Agent’s responses. For this
task, the extracted trajectory includes:

   • Duplicate the image layer.

   • Convert the duplicated layer into a Smart Object.

   • Apply the “Lighting Effects” Smart Filter.

B. Details of Experiments
B.1. Prompt Details
In this section, we present the prompts used in our experiments. We found that when both the Semantic Planning Prompt
and the Task Execution Prompt are provided to MLLMs simultaneously, the models tend to generate a large number of
invalid PyAutoGUI commands during execution, which often leads to task failure.
Therefore, we separate the two types of prompts: Section B.1.1 provides the Semantic Planning Prompt, while Section B.1.2
provides the full Task Execution Prompt (which also includes the complete action space description).
During the evaluation process, MLLMs first generate a complete agent trajectory based on the Semantic Planning Prompt
for conducting NDEC evaluation; subsequently, they complete the task according to the Task Execution Prompt. This
design ensures that a full agent trajectory is obtained for NDEC analysis regardless of whether the GUI agent successfully
completes the task.

 • Image quality degradation: Image editing models often perform destructive modifications on the original pixels during

B.3. Failure Analysis
We selected 150 failed cases and analyzed them based on screen recordings of task execution, identifying three primary
failure patterns: Perceptual Errors (approx. 67%), where agents fail to locate specific controls or fine-grained menu
options; Task Planning Errors (approx. 20%), where high-level plans fail to translate into concrete navigation paths; and
Execution Control Errors (approx. 13%), characterized by a lack of dynamic adjustment, such as relying on static text
input rather than interactive sliders.

Beyond these statistical patterns, a qualitative deep dive reveals several structural limitations that hinder GUI agents in
professional Photoshop environments:

  • Insufficient Knowledge of Professional Workflows and Conventions: The models exhibit a profound lack of
    familiarity with software-specific expertise, particularly regarding shortcuts and terminology. While experienced
    users utilize shortcuts like Ctrl+Shift+U for instant desaturation, agents laboriously navigate nested menus. More
    critically, agents often misapply universal shortcuts; for instance, they mistakenly use Ctrl+A to clear numeric
    inputs, which in Photoshop selects the entire pixel canvas instead. This leads to input errors, such as appending digits
    to existing values (e.g., entering “3050” instead of replacing “30”). Furthermore, models frequently misinterpret
    professional terms, such as confusing “highlights” in portrait retouching with general “lighting,” or resorting to crude
    brush strokes rather than professional pipelines involving masks and blending modes.
  • Deficiencies in UI Grounding Precision: Despite being pre-trained on large-scale UI datasets, these models frequently
    mislocate elements in Photoshop’s dense interface. We observed consistent spatial offsets: even when a planner
    correctly identifies the “Filter” menu, the execution agent may repeatedly click “Select” or “3D” (the adjacent menus).
    This inaccuracy fundamentally undermines fine-grained spatial reasoning. While agents can handle coarse commands
    like “select the center,” they fail entirely at tasks requiring precise regional identification, such as selecting a specific
    tree within a complex landscape.
  • Absence of Aesthetic Awareness and Visual Coherence: The models’ editing behaviors remain mechanical, lacking
    foundational knowledge of photography and post-processing aesthetics. For example, when tasked with adding a
    “soft glow,” agents often apply raw orange color strokes without considering light direction, perspective, or global
    illumination consistency. Although such aesthetic deviations are not always categorized as technical failures under our
    current evaluation metrics, they fall significantly short of professional standards.

B.4. Human-in-the-loop User Study
In our human-in-the-loop experiment, we recruited 24 undergraduate students majoring in computer-related disciplines. All
participants possessed basic software operation skills but were complete novices in Photoshop: each reported a total usage
time of less than two hours and had not received any form of image-editing training.
To compare the effectiveness of different modes of human–AI collaboration, the 24 participants were evenly divided into
three groups:

  • Unassisted novice user: participants attempted to complete the tasks without any additional help.

  • Novice user with internet access: participants were allowed to freely consult online tutorials or documentation.
  • Novice user assisted by a GUI agent: participants received real-time step-by-step natural-language guidance from
    GPT-4o (without generating executable code).

All groups were tested on the same set of 60 tasks (20 Easy, 20 Medium, 20 Hard). For each participant, we recorded both
the task success rate and the average completion time of successfully completed tasks. The individual results are shown in
Figure 8, Figure 9, and Figure 10. We subsequently averaged the results within each group to obtain the overall performance
under the three experimental conditions, as presented in Figure 4.
