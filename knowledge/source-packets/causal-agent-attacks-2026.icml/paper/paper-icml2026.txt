A. Graph Representations
CausalTrace employs three graph representations with increasing semantic richness. A generic graph G = (V, E) provides
structural connectivity but lacks semantic constraints on nodes or edges. Agent trajectory graphs extend this formalism by
introducing typed nodes and labeled edges.


                                                     Gagent = (V, E, τ, λ)                                                (3)

The function ϕ : V → {Task, Observation, Action, Result} assigns node types and λ : E → {temporal, data, causal}
assigns edge labels. Table 1 and Table 2 specify the semantics of each type.

                                                Table 1. Node Type Specification

                            Type            Symbol       Description
                            Task            T            Initial instruction provided to the agent
                            Observation     O            Information perceived from environ-
                                                         ment
                            Action          A            Operation executed by agent
                            Result          R            Outcome of execution


                                                Table 2. Edge Type Specification

                             Type         Notation      Semantics
                             Temporal     et            Sequential ordering in execution
                             Data         ed            Information flow between nodes
                             Causal       ec            Cause-effect relationship

Causal graphs constitute the most expressive representation, augmenting the agent trajectory graph with structural equations
and an injection variable.
                                                    Gcausal = (V, E, F )                                                  (4)

The set F = {fv : v ∈ V } specifies structural equations determining each variable from its parents. For attack detection,
the node set is augmented with an injection variable I representing adversarial content. The causal structure enables
counterfactual queries via Pearl’s do-calculus, formalized through the Probability of Necessity.


                                           PN = P (MI←0 = 0 | I = 1, M = 1)                                               (5)

The term MI←0 denotes the counterfactual outcome under intervention do(I = 0). High PN indicates the injection was a
necessary cause of the malicious outcome. Table 3 summarizes the distinguishing characteristics of each representation.

                                        Table 3. Comparison of Graph Representations

                         Property        Generic                Agent Trajectory       Causal
                         Node typing     None                   ϕ:V →T                 τ + Injection
                         Edge typing     None                   λ:E→L                  Causal only
                         Semantics       Structural             Behavioral             Interventional
                         Queries         Path, connectivity     Pattern matching       Counterfactual

C. Event Schema
Each trajectory event follows the schema specified in Table 5. The parents field captures structural causality from
the agent’s execution flow without requiring explicit data flow annotations. Event types span navigation, observation,
LLM reasoning, action execution, network requests, and memory operations. The schema supports both single-agent and
multi-agent trajectories through the agent identifier field.

D. Edge Inference Rules
For trajectories without explicit parent annotations, structural edges are inferred using the rules in Table 6. Sequential edges
connect consecutive events within the same agent turn, using a 30-second temporal threshold based on typical LLM response
latencies. Delegation edges connect orchestrator actions to sub-agent first events when the action metadata indicates task
delegation. Memory edges connect write and read operations on the same memory key, even across sessions, enabling
detection of memory poisoning attacks.

D.1. Provenance Marker Specification
This section specifies the provenance marker mechanism summarized in Section 4.2. Each provenance marker takes the
form of a metadata tuple (uuid, source domain, H(timestamp∥node id)) where H denotes a SHA-256 hash. Markers are
symbolic tags attached as node attributes in the causal graph. They are not inserted into the agent’s text stream and the agent
is unaware of their presence.
During generation, every node receives a marker based on its origin field at graph construction time. User-instruction nodes
receive a root marker indicating trusted provenance. External observation nodes receive markers tagged with their source
domain. Generation is deterministic and requires no LLM inference.
During propagation, markers follow edges according to edge type. Data-dependency edges within the same domain
propagate the parent’s marker to the child, preserving trusted lineage. Trust-transfer edges and cross-domain edges do not
propagate markers. When an agent follows instructions from an external source, the resulting action node lacks the root
marker, creating a provenance gap.

We formalize the counterfactual analysis on this trajectory using the structural equation from Section 4. The trajectory
comprises five nodes, with the attack chain spanning four nodes from the injection source to the malicious outcome.
     v1 (NAV) → v2 (OBS+injection) → v3 (LLM CALL) → v4 (ACTION: create token) → v5 (NET REQ: transmit to attacker)

Observed world (I=1, M =1). The injection node v2 contains explicit override language (”ATTENTION AGENT. . . you
MUST”), yielding injection strength s = 0.9. Applying the structural equation P (Mv ) = βI · I · s + βT · T · (1 − I) + Uv
at each node with βI = 0.75 and βT = 0.05, the injection term contributes 0.75 × 0.9 = 0.675 per node. Each node is
observed active (P = 1), so abduction infers noise Uv = 1 − 0.675 = 0.325 at each injection-influenced node.
Counterfactual world (do(I=0)). Graph mutilation removes injection content from v2 and sets I = 0 throughout the
chain. Without injection, the legitimate task (”add a reaction”) provides no task-relevant influence toward creating deploy
tokens or transmitting credentials externally, so T = 0 for nodes v4 and v5 . Each node’s counterfactual activation reduces to
P (v|do(I=0)) = βT · T + Uv . For nodes on the malicious path with T = 0, this equals Uv = 0.325.

of exogenous noise across nodes, the counterfactual chain probability is the product of individual activations.

A single-step attack with the same parameters would yield PN = 1 − 0.325 = 0.675, a substantially weaker signal. This
formalizes the intuition that multi-step attacks leave stronger causal signatures than single-step attacks, and explains why
CausalTrace achieves higher detection confidence on longer attack chains.
To evaluate the task-conditioned counterfactual on user-authorized cross-domain actions, we construct a 560-trajectory test
set spanning seven task templates (install, configure, setup guide, data apply, migrate, translate, benchmark). Each trajectory
follows the pattern of navigating to external documentation, extracting instructions, and executing them as directed by the
user task. Ground truth labels are benign. The detection without task conditioning flags 85.7% as attacks (480 of 560) due to
cross-domain edges and taint paths matching injection signatures. With task-conditioned counterfactual analysis, all causal
methods produce zero false positives across the full test set, correctly identifying that the flagged outcomes align with the
user’s stated task specification.
