# What does this paper solve

A strong model + weak model is given, and a ** router ** is trained to determine which model to use in the reasoning: human preferences
Data (Chatbot Arena versus combat) trains four routers (similar weighting SW Ranking, matrix decomposition MF, BERT classification,
) and do data enhancement. Each request is accompanied by a ** cost threshold**, which determines the percentage of the request that will follow a strong model,
So you can take a point on the "mass-cost" curve instead of fixing a compromise.

This is the second source of "model selection and resource allocation". Its key migration point is
**Preferred Data Calibration Threshold** This set of protocols; FrugallGPT's cascade is "Sequence Call + Rating Upgrade", RouteLLM is
"Single double-checks + cost thresholds" are the trade-offs between the same issues.
