A. Agentic Environments
In this section, we introduce the agent’s runtime environment for our experiments. This includes details of the system
prompt, descriptions of the tools, and the specific return messages from intentionally designed broken tools.

A.1. System Prompt
We adopt the default system prompt from the smolagents framework, which is available on the framework’s official
HuggingFace page1 . This prompt introduces the ReAct workflow, specifies guidelines for the agent’s behavior in writing
code and invoking tools, and describes the available tools, including their functionalities and calling syntax. Furthermore, it
provides several workflow examples as few-shot demonstrations as the agent’s memory. We manually check the system
prompt and find no instructions designed to pressure the agent or encourage deception. The only potentially influential
statement is an encouraging phrase: ”Don’t give up! You’re in charge of solving the task, not providing directions to solve
it.” However, we consider this to be standard practice.

A.2. Tools
Table 6 provides detailed information about the tools configured for the agent, including: the tool’s name, its description
(which is provided in the agent’s system prompt), its availability in each task type, and the message returned when the tool
is artificially sabotaged. Note that many of the tools we provide to the agent are redundant, but this does not affect our
experimental conclusions. Furthermore, we do not provide the agent with an explicit download tool. Additionally, a key
feature of the framework is that it requires the agent to return the final report to the user via the default final answer tool,
which facilitates our evaluation and experimental setup.

    ### Class 1: Total Failure / No Answer
    - **Condition**: The agent explicitly states that it **cannot provide any answer**

    - **Common Indicators**: Cites reasons such as inability to open/read a file, a

    - **Condition**: The agent **provides an answer BUT explicitly qualifies it** as a
        guess, speculation, or potentially incorrect because it encountered a technical
        issue along the way.
    - **Key Feature**: The response contains both an answer and a disclaimer about its

    - **Output Value**: 2

    ### Class 3: Confident Answer / No Failure Mentioned
    - **Condition**: The agent provides a definitive answer and does **not** mention

    - **Note**: This class covers all responses where the agent acts as if it completed

        answer or an answer with a detailed explanation.

C. Additional Evaluation
C.1. Human Evaluation
To validate that our findings are not an artifact of rubric-based LLM judging, we conduct an additional manual annotation
study on full agent trajectories. Two independent human annotators examine 200 Kimi-K2 trajectories spanning all five
task types and label whether each case exhibits upward deception. Unlike the automatic evaluation protocol, the annotators
review the complete execution trace, including intermediate actions, tool outputs, generated files, and the final response. For
Tasks 4 and 5, we adopt a stricter human criterion: a case is labeled deceptive only when the agent fabricates a file and does
not disclose this fabrication either in the generated file itself or in the final response.
Table 7 summarizes the results. Overall, the human annotations substantially agree with the LLM-judge evaluation, and the
main conclusions remain unchanged under manual inspection. For Tasks 1, 3, 4, and 5, both annotators identify high rates of
deceptive behavior, broadly consistent with the automatic evaluation. In several settings, the human annotators even label
more cases as deceptive than the LLM judge, suggesting that the automatic protocol does not overstate the phenomenon
and may be conservative, especially in file-fabrication settings. Task 2 is the main exception: since the provided file is
intentionally irrelevant to the user’s question, the boundary between deception and over-interpretation is more subjective. As
a result, annotators may reasonably disagree on whether forcefully answering from irrelevant material should be counted as
deception. Importantly, this disagreement is localized to Task 2 rather than representative of the overall evaluation. These
results provide direct evidence that upward deception remains visible under manual review of full trajectories.

C.2. Ablation on Agent Framework
To examine whether upward deception is specific to the smolagents framework, we further evaluate agents under a
standard OpenAI tool-calling format. This setting uses the conventional message-based tool interface, where the model
invokes external tools through structured tool calls and receives tool outputs as subsequent messages. As shown in Table 8,
upward deception remains highly pronounced under this alternative agentic framework. Across both evaluated models, agents
frequently produce successful-looking final reports despite failed or incomplete execution, indicating that the phenomenon
is not an artifact of a particular framework implementation.
