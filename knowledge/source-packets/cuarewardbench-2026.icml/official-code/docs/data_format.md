# Data Format

## Benchmark Layout

```text
data/
├── annotations/
│   └── cuarewardbench-v0.4.json
├── trajectories/
│   └── osworld_verified/
│       └── {model_setting}/{task_type}/{task_id}/
└── manifest.jsonl
```

Each trajectory directory should contain:

```text
step_*.png       # screenshots used by the reward prompt
traj.jsonl       # primary action trace
result.txt       # rollout status / legacy result marker
runtime.log      # rollout log, not required by benchmark scoring
traj_tran.jsonl  # optional derived JSONL; not required when traj.jsonl exists
```

## Annotation JSON

`data/annotations/cuarewardbench-v0.4.json` is a JSON list. Minimal item shape:

```json
{
  "model_setting": "claude-4-sonnet-20250514-15steps",
  "task_type": "gimp",
  "task_id": "7a4deb26-d57d-4ea9-9a73-630f66a7b568",
  "result": "1",
  "step_num": "7",
  "instruction": "...",
  "key_good_in_success": [3, 5],
  "key_bad_in_success": [],
  "key_good_after_bad_in_success": [],
  "comments": []
}
```

See `docs/annotation_protocol.md` for field semantics.

## `traj.jsonl`

`traj.jsonl` is a line-delimited JSON file. Each line is one action step. Common fields:

| Field | Description |
| --- | --- |
| `step_num` | 1-based action step. |
| `action_timestamp` | Timestamp used in screenshot filename. |
| `action` | Raw action code or command. |
| `response` | Optional model response / thought-action text. |
| `reward` | Legacy rollout reward field. |
| `done` | Whether the rollout ended after this step. |
| `info` | Extra rollout metadata. |
| `screenshot_file` | Screenshot filename for the step. |

The benchmark evaluator currently reads `action` from `traj.jsonl` and pairs it with `step_*.png` screenshots.

## `traj_tran.jsonl`

`traj_tran.jsonl` is auxiliary. In the observed `uitars15-7b-15step` cases, it is a deterministic UTF-8 / `ensure_ascii=False` rewrite of `traj.jsonl`; the preprocessing script can regenerate it and verifies the generated bytes against `data/manifest.jsonl`.

For public benchmark evaluation, `traj.jsonl` is the primary required trace file. We keep `traj_tran.jsonl` unchanged where it appears in the current manifest.

## Manifest JSONL

Each line in `data/manifest.jsonl` describes one expected normalized trajectory:

```json
{
  "model_setting": "...",
  "task_type": "...",
  "task_id": "...",
  "rel_dir": "{model_setting}/{task_type}/{task_id}",
  "num_screenshots": 10,
  "screenshots": [{"name": "step_1_...png", "size": 123, "sha256": "..."}],
  "traj_files": [{"name": "traj.jsonl", "size": 456, "sha256": "..."}]
}
```

Use:

```bash
python3 scripts/prepare_manifest.py
python3 scripts/verify_data.py
```

## New-Agent Trajectory Evaluation Layout

`python3 -m cuarewardbench.cli.eval_trajectory` expects a rollout directory shaped as:

```text
/path/to/trial/
└── {task_type}/
    └── {task_id}/
        ├── traj.jsonl
        ├── result.txt              # must contain PENDING_FOR_RM by default
        ├── step_reset_*.png        # optional initial state
        ├── step_1_*.png
        └── ...
```

Use `scripts/run_eval_trajectories.sh` for single-trial or merged multi-trial evaluation.
